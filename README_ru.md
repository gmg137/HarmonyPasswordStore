# HarmonyPasswordStore

[简体中文](README.md) | [English](README_en.md) | [Русский] | [Deutsch](README_de.md) | [繁體中文](README_zh-TW.md)

Нативный клиент [pass](https://www.passwordstore.org/) для HarmonyOS (HongMeng), совместимый со стандартным форматом хранилища pass; дизайн основан на [Android-Password-Store](https://github.com/agrahn/Android-Password-Store). Отображаемое имя приложения — **PasswordStore**.

## Возможности

| Функция | Описание |
|---------|----------|
| Полная совместимость с pass | Стандартная структура каталогов и GPG-шифрованные записи (`.gpg`); в `.gpg-id` — по одному ключу на строку (отпечаток / Key ID / email), поддерживаются комментарии в конце строки и маркер `!` для принудительного выбора подключа; совместимо с pass CLI и настольной экосистемой |
| Постквантовая криптография (PQC) | Импорт и использование ключей GnuPG algo 8 (ML-KEM-768 + X25519 / brainpoolP256r1 / brainpoolP384r1), полная совместимость с gpg 2.5+; обычные и PQC-ключи могут быть получателями одной записи |
| Три режима поиска | Нечёткий / точный / **по содержимому** — режим «по содержимому» расшифровывает записи и ищет по значениям полей, кроме самого пароля (пароль никогда не участвует в поиске); у совпавших строк отображается фрагмент |
| Генератор паролей | Криптографически стойкий источник случайности; длина, наборы символов, исключение похожих символов; парольные фразы Diceware с оценкой энтропии |
| Управление PGP-ключами | Импорт из текста или файла (armor и двоичный формат распознаются автоматически), генерация ключей EdDSA/RSA, смена парольной фразы, экспорт в `.asc`, выбор ключа шифрования по умолчанию |
| Синхронизация Git | clone / pull / push / commit по SSH и HTTPS; трёхступенчатая TOFU-проверка отпечатка хоста (подтверждение при первом подключении / доверенный / предупреждение о несовпадении); принудительная отправка; pull с rebase; HTTPS-прокси |
| Автозаполнение | Интеграция с системным фреймворком автозаполнения; подбор учётных данных по имени пакета / домену |
| Биометрическая разблокировка | Отпечаток / распознавание лица (системный запрос вызывается автоматически); автоблокировка по таймауту сессии; при блокировке очищаются парольные фразы и кэши расшифровки в памяти |
| Управление файлами | Дерево каталогов, перемещение / переименование записей (с автоматическим перешифрованием между каталогами с разными ключами), создание и удаление папок |
| Формат файла пароля | Двоичный (как в настольном pass) или ASCII armor, переключается в любой момент (влияет только на новые записи) |
| Безопасность буфера обмена | Скопированный пароль автоматически удаляется по таймеру; кратковременная задача гарантирует очистку даже в фоне |
| Локализация | 简体中文, 繁體中文, English, Deutsch, Русский (следует системному языку, переключается в приложении) |

## Требования

- Смартфон HarmonyOS (API 26+)

## Сборка и установка

Перед первой сборкой создайте локальную конфигурацию подписи из шаблона (файл содержит пути и пароли материалов подписи и **не коммитится**):

```bash
cp build-profile.example.json5 build-profile.json5
```

Затем откройте проект в DevEco Studio и через **File → Project Structure → Signing Configs** (Automatically generate signature) сгенерируйте отладочные материалы подписи в этот файл (от него зависят и сборки из командной строки).

После этого собирайте в [DevEco Studio](https://developer.huawei.com/consumer/harmonyos/) (с HarmonyOS SDK) или из командной строки (Hvigor):

```bash
hvigorw assembleHap                                            # отладочный HAP
hvigorw -p buildMode=release assembleHap                       # release (включает обфускацию ArkTS)
hvigorw -p product=default -p buildMode=release assembleApp    # релизный пакет .app
```

Расположение результатов: HAP — в `entry/build/default/outputs/default/`, .app — в `build/outputs/default/` в корне проекта.

Нативные статические библиотеки PGP (Rust) и Git (libgit2) предварительно собраны в репозитории (aarch64 / x86_64); для обычной сборки инструменты Rust не нужны. Для изменения нативного кода см. `entry/src/main/cpp/rpgp_wrapper/` (тесты Rust: `cargo test --release`).

## Совместимость с форматом хранилища pass

- Запись — это `<каталог>/<имя>.gpg`; первая расшифрованная строка — пароль, далее поля `user:` / `email:` / `phone:` / `notes:` и произвольный текст
- `.gpg-id` в корне хранилища (или любом подкаталоге) задаёт ключи шифрования; поддерживаются несколько ключей и все варианты записи pass
- Расшифрование выбирает ключ по **фактическим получателям в шифротексте** (как `pass show`); при отсутствии ключа выводится понятная ошибка вместо повторных запросов парольной фразы
- Созданные шифротексты можно проверить напрямую через `gpg --decrypt` на компьютере

## Безопасность

- **Локальные данные прежде всего**: никаких облачных сервисов; пароли существуют только в виде зашифрованных файлов на устройстве и в настроенном вами Git-удалённом репозитории
- **Жизненный цикл открытого текста**: расшифрованное содержимое существует только в памяти; кэш поиска хранит лишь производный текст значений полей (никогда — сам пароль); при блокировке или уходе в фон всё очищается, включая нативный кэш разблокированных приватных ключей
- **Шифрование учётных данных**: конфиденциальные данные (например, учётные данные Git) шифруются при хранении средствами HUKS; буфер обмена автоматически очищается по таймеру
- **Безопасность журналов**: в журналы никогда не попадают пароли, ключи и открытый текст
- **Защита импорта**: armor нормализуется при импорте (защита от однострочного base64, ломающего нативный разбор); двоичные шифротексты проходят проверку CRC24 перед записью

## Модульные тесты

ArkTS (LocalUnit, запускаются из DevEco Studio; новые файлы нужно вручную регистрировать в `List.test.ets`):

```
entry/src/test/
├── List.test.ets               # точка входа наборов тестов
├── PasswordFileParser.test.ets # разбор формата pass / сериализация / поисковый текст и фрагменты
├── PgpPacketParser.test.ets    # преобразование armor (CRC24 по векторам RFC 4880) и отпечатки vs. gpg
├── PasswordGenerator.test.ets  # длина / наборы символов / исключение похожих / энтропия
├── CredentialMatcher.test.ets  # сопоставление для автозаполнения / проверка RP ID
└── PathSafety.test.ets         # защита от обхода пути (ввод пользователя и содержимое репозитория)
```

Rust (27 тестов, включая сквозное взаимодействие с gpg и PQC):

```bash
cd entry/src/main/cpp/rpgp_wrapper && cargo test --release
```
