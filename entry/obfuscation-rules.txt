# 必须与代码标识保持一致的属性名
#
# 属性名混淆只改「定义与引用」，但以下名字同时以字符串形式出现在别处，
# 改了就对不上：
# - 设置对象的**字段名**（`AppSettings` / `GitConfig`）：这些以属性访问形式读写，
#   登记属**防御性保留**——凡「按名字取字段」的路径（落盘 JSON、native 边界、
#   跨版本读旧数据）改了名就对不上。列表与当前字段名**并非严格一一对应**
#   （如 `passwordFileOrganization` 已随字段改名成 `fileOrganization` 而失效），
#   属无害的过度保留：多留不错，漏留才危险。
# - **不要误以为这些是 Preferences 键**：`PrefKeys` 的值是**字符串字面量**
#   （`'store_path'`、`'git_config_json'`…），而属性混淆只改标识符、不动字符串，
#   升级后旧键值照样读得到，本身并不需要登记（下面混进来的 `git_config_json`
#   就属这一类）。

# - NAPI 模块的函数名
#
# **release 构建下最容易踩的坑**：`-enable-property-obfuscation` 会把
# `hpsNative.gitClone(...)` 这类属性访问一起改名（实测变成 `hpsNative.a8`），
# 而 native 侧注册的属性名是 .so 里的字符串字面量、不会跟着改，
# 于是取到 undefined、调用直接抛 "a8 is not callable, a8 is undefined"，
# 被 NativeBridge.callSafely 兜成「native call failed」。
# 后果是 release 包里**所有** native 能力（PGP 加解密、密钥生成、git 操作）全部失效，
# 而 debug 包（不做混淆）一切正常——真机实测：点击「初始化仓库」报 native call failed。
# 新增 NAPI 函数时必须同步加到这里（与 hps_napi.cpp 的 desc[] 一一对应）。
